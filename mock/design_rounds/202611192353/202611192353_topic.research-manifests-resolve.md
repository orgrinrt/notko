# A research manifest resolves

Round 202611192252 moved the crates under `mock/crates/`, and round 202611192330 put every moved research file back to its bytes on `dev` so the move would be a move. Seven sketch manifests name the crates by a relative path, and those paths still pointed at where the crates sat before the move, so none of the seven resolved: `cargo metadata` failed on each with the old directory missing. One of them is `carrier-as-a-typestate-parameter`, the sketch `docs/design/notko-hlist-product-carrier.md` cites as the one that showed the carrier working, so the design was citing evidence nobody could rebuild. Round 202611192330 said the move was a move, and for these seven it was not.

A manifest path is the place a sketch runs from, not the experiment it ran, so keeping the bytes does not cover it. The same repoint was already made for the test fixtures of `notko-macros`. The seven paths now name `crates/notko` and `crates/notko-hlist`, a commit of research files that needs no round.

What does need the round is the check for the class. Nothing failed when the paths went stale, and the review that found it ran `cargo metadata` by hand. `a_probe_crate_says_it_is_a_probe.rs` already reads every tracked manifest under `research/` to see that each one refuses to publish, and the same reader can check that every `path` such a manifest names exists: a directory holding a `Cargo.toml` for an inline dependency table, an existing file for a target's `path`. A second test shows the path reader can fail, on a commented line, and on a directory with no manifest in it.

No design changes. The doc changelist of this round says so and nothing else.
