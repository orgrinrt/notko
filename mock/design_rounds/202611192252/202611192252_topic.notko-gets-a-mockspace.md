# Topic: notko gets a mockspace

**Date:** 2026-11-19
**Phase:** TOPIC
**Scope:** the repository's layout, which gains a mockspace and the place for a bench harness. No
crate's source changes in what it does.
**Origin:** the stack record, `clause-dev/.shared/research/202611150830_stack-path/42-*.md`, "Where
notko's benches live", ticket `where_do_notko_s_benches_live`.

## The call

The record, verbatim:

> Options shown: 1. Notko gets a mockspace with a bench harness. 2. In hilavitkutin's harness. 3. No
> benches of its own.
>
> Chosen: Notko gets a mockspace.

The intent is the first option: notko's benches live in notko, under its own mockspace and that
mockspace's bench harness. The rest of the record's paragraph, that the workspace rule naming notko as
a repository with no mockspace is corrected in the same work, is kept for provenance and is done in
clause-dev beside this round.

## The layout

The crates move under `mock/crates/`, one directory each, and the workspace manifest becomes
`mock/Cargo.toml`, the shape arvo, hilavitkutin, lato and kirjo already have. Consumers name notko by
its git repository and a package name, and cargo finds a package anywhere in a git checkout, so no
consumer manifest changes for the move.

The root crate `notko` was the workspace root as well. As a member under `crates/` it carries its own
readme, since a package cannot reach above itself, and the repository's readme at the root stays the
page a visitor reads; a test holds the two one text. The repository checks among its tests (the
readme claims, the publish checks, the probe check) read the workspace at `mock/` instead of at the
crate.

`research/` becomes `mock/research/`, where the corpus tools read it. `docs/design/` stays where it
is: it is authored, and it is what stands in for a canon here, since notko declares none.

The feature matrix under `scripts/` runs the same arms from `mock/`. Its arms are a test runner, and
whether they belong in a mockspace tool is a ticket rather than this round.

## What this round does not do

No source changes in behaviour, and no test is weakened. The bench of the product's compile time is
the next round, on this mockspace.
